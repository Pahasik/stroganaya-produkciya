# Сайт производителя сухой строганой продукции

Одностраничный B2B-сайт для сбора оптовых заявок: клеёная имитация бруса, клеёный планкен,
калиброванная и другая строганая продукция.

Стек: **Vite 8 + React 19 + TypeScript + Tailwind CSS v4**. Шрифты (Manrope, Inter)
подключены локально через `@fontsource-variable` — внешних запросов у сайта нет.

## Запуск

```bash
npm install
npm run dev
```

Сайт откроется на `http://localhost:5173` (или на указанном порту).

| Команда | Что делает |
| --- | --- |
| `npm run dev` | Локальная разработка |
| `npm run build` | Проверка типов + production-сборка в `dist/` |
| `npm run preview` | Просмотр собранной версии |
| `npm run lint` | Линтер (oxlint) |
| `npm run images` | Пересборка WebP из `raw-images/` в `public/images/` |

## Публикация на GitHub Pages

Деплой настроен в `.github/workflows/deploy.yml` и запускается автоматически
при каждом пуше в ветку `main`.

Базовый путь берётся из имени репозитория (`VITE_BASE=/<имя-репозитория>/`),
поэтому репозиторий можно переименовать — ничего чинить не придётся.
Локально `base` остаётся `/`, разработке это не мешает.

Разовая настройка после создания репозитория:
**Settings → Pages → Build and deployment → Source: GitHub Actions.**

Сайт будет доступен по адресу `https://<логин>.github.io/<имя-репозитория>/`.

## Форма заявки

Форма реализована полностью: валидация, маска телефона, состояния загрузки, успеха и ошибки,
сводка ошибок с переходом к полям, поддержка клавиатуры и скринридеров.

**Обработчик заявок пока не подключён.** Пока переменная окружения `VITE_LEAD_ENDPOINT`
не задана, форма работает в демонстрационном режиме: она проверяет данные и показывает
все состояния интерфейса, но **не отправляет запрос** — вместо ложного «Заявка отправлена»
пользователь видит честное сообщение о демонстрационном режиме.

Чтобы включить реальную отправку, создайте файл `.env.local`:

```bash
VITE_LEAD_ENDPOINT=https://ваш-домен.ру/api/lead
```

Обработчик должен принимать `POST` с JSON-телом типа `Lead`
(см. `src/lib/submitLead.ts`) и отвечать кодом 2xx. Если вместо своего бэкенда
используется CRM или внешний сервис форм — замените тело функции `sendToEndpoint`
в том же файле.

## Изображения

Изображения сгенерированы для демонстрации типа продукции и характера производства.
Это **не документальные снимки конкретного производства**, о чём прямо сказано в галерее
и в подписях под изображениями. На них нет чужих логотипов, товарных знаков,
узнаваемых лиц и читаемых надписей.

Исходники лежат в `raw-images/`, оптимизированные WebP нескольких размеров —
в `public/images/`. После замены исходников запустите `npm run images`:
скрипт пересоберёт WebP, размытые заглушки и `src/data/image-manifest.json`.

Перед публикацией имеет смысл заменить их на реальные фотографии производства.

## Структура

```
src/
  components/        секции страницы
    ui/              переиспользуемые примитивы
      Picture.tsx        адаптивное изображение (WebP, srcset, lazy, LQIP)
      ProfileDrawing.tsx технические чертежи сечения 20 × 135 мм
      Reveal.tsx         появление блоков при прокрутке
      icons.tsx          линейные иконки
  data/content.ts    ВЕСЬ текст и данные сайта — правки контента здесь
  lib/submitLead.ts  отправка заявки, маска и валидация телефона
  index.css          дизайн-токены (цвета, шрифты) и базовые стили
```

Контент отделён от вёрстки: цены, характеристики, преимущества, вопросы FAQ и шаги
заказа лежат в `src/data/content.ts`.

## Проверено

- Сборка и типы: `npm run build` — без ошибок; линтер — без замечаний.
- Адаптивность 360 / 768 / 1024 / 1440 px, горизонтального скролла нет
  (проверено обходом DOM, а не только `overflow: hidden`).
- Один `h1`, логичная иерархия заголовков, `alt` у всех изображений.
- Все якорные ссылки ведут к существующим секциям.
- Консоль без ошибок и предупреждений.
- Форма: пустая отправка, некорректный телефон, объём ниже 10 м³, успешный сценарий.
- Клавиатурная навигация, видимые focus-состояния, `prefers-reduced-motion`.
